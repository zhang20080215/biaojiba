# 标记吧：首页与底部导航改造方案 V1

日期：2026-10-11。交付范围：产品方案与实施拆分，尚未修改业务代码或发布。

建议采用「首页 / 发现 / 记录 / 我的」四个底部标签。首页承接推荐与继续使用，发现提供完整内容目录，记录承接个人标记与每日记录，我的管理身份、偏好和服务。核心体验是：找到感兴趣的主题 → 完成标记 → 下次继续 → 回顾与分享。

## 1. 方案依据与数据边界

本方案核对了当前工作区的 app.json、category 页面、主题注册表、人数统计、跨榜同步、埋点，以及 9 月用户反馈报告；没有读取线上实时人数榜或验证当前线上界面。文中的卡片名称只作布局举例，不代表真实热度排名。

现状有四个明显问题：

1. 首页先后展示个人资料、每日标记、豆瓣专列、旅行打卡、猜电影、主题搜索和主题全集，用户在看见完整内容目录前已穿过多个专区。
2. 主题顺序仍是「个人置顶 → 豆瓣电影 / IMDb 固定前置 → 原配置顺序」，参与人数尚未决定排序。
3. 分类混合了内容领域和榜单来源：电影、读书、旅行与奥斯卡并列。内容继续增加后，这种分类越来越难找。
4. 每日记录与主题进度分散，没有统一的回访入口。用户反馈中出现了自建命名片单 / 书单、最爱与分享需求，应给个人内容留出位置。

人数统计存在需要先处理的边界：

- category.js 将统计值统一加 100，再按百位向下取整展示；聚合失败时还可能按标记条数除以 3 估算，部分失败被当成 0 继续加 100。
- 全部加同一常数本身不改变精确值的相对顺序，但估算、取整和失败值会影响可信度。推荐服务不得直接用展示字段排序。
- 现有跨榜同步会给其他榜单写入标记，因此「在榜内有标记的人」不等于「主动使用这个榜单的人」。当前记录快照也不能直接代表历史累计参与人数。
- 仓库里的 7 月全主题分析报告仍为待生成状态，旧分析云函数的主题清单也未覆盖现在的全部主题；不能用它直接生成当前完整排行。
- 4—5 月报告只能作为历史问题线索，不能将其中留存数当作本次上线基线。

## 2. 底部导航与职责

| 标签 | 用户来这里做什么 | 首期内容 | 后续扩展 |
|---|---|---|---|
| 首页 | 找到值得开始的内容，继续上次操作 | 搜索入口、继续标记、热门主题精选、新上主题、轻量工具入口 | 根据兴趣排序的推荐、专题策划 |
| 发现 | 找到某一类内容或某个具体主题 | 分类、主题搜索、热门 / 最新排序、完整主题目录、工具与玩法 | 更多领域、系列专题、公开自建清单 |
| 记录 | 查看和继续自己的记录 | 常用主题、参与中的主题与进度、每日记录入口 | 跨主题作品库、自建清单、年度回顾 |
| 我的 | 管理个人资料与使用偏好 | 头像昵称、主题外观、订阅管理、许愿、反馈、关于、已有权益状态 | 数据管理、个人展示设置 |

四个入口按用户任务划分，电影、读书、旅行等领域放在发现页内。这样新增内容时不必改变底部导航。四个标签使用等宽的「图标 + 两字文字」，选中态同时改变图标和文字，保持现有主题色体系；不设置凸起的中间加号，不使用常驻红点提示普通内容更新。

「记录」是个人内容的唯一完整入口；「我的」最多提供“查看我的记录”快捷链接，不复制另一套记录列表。「首页」只做精选，不重复完整目录。四页必须一同具备上述最小内容后再发布，避免先上线空标签。

## 3. 首页结构

### 3.1 推荐布局

```text
标记吧
[ 搜索片单、书单、旅行主题           ]

继续标记                         全部记录 ›
[最近操作的主题 · 已完成数量 · 继续]   ← 有记录才显示，最多一张

大家都在标记                     更多热门 ›
[封面 / 名称 / 人数] [封面 / 名称 / 人数]
[封面 / 名称 / 人数] [封面 / 名称 / 人数]
[封面 / 名称 / 人数] [封面 / 名称 / 人数]

最近上新                         查看全部 ›
[新主题一] [新主题二]

[记电影] [记读书] [记运动] [记喝水]   ← 紧凑的一行快捷入口
[电影评分查询] [每日猜电影]           ← 轻量入口

首页          发现          记录          我的
```

首屏优先露出至少一排热门主题；以 375 × 667 逻辑尺寸验收，在更窄屏和大字体下允许自然换行。老用户的继续卡压缩高度，不挤掉首排热门卡片。热门区首期最多 6 张、2 列 3 行；长标题最多 2 行，人数固定在文字信息区，图片失败使用已有渐变占位。

### 3.2 模块规则

| 模块 | 具体规则 |
|---|---|
| 顶部 | 缩小品牌区，移走登录卡、反馈卡和大段口号。首次进入直接展示内容，不要求先完善头像昵称。身份获取失败时明确提示记录保存状态 |
| 搜索 | 首期明确搜索的是主题名称、作者、类型和来源。电影评分查询保留独立入口，避免用户误以为这里能搜索任意作品 |
| 继续标记 | 最多 1 张，按最近一次主动标记 / 记录选择；只有浏览记录时可显示“最近浏览”，不伪称已参与。点击回原业务页；无记录就整块隐藏 |
| 热门精选 | 6 张精选卡，展示领域、完整主题名、经核验的人数；“更多热门”进入发现的热门排序。个人置顶只影响个人常用，不篡改公共热度 |
| 最近上新 | 最多 2 张，按真实上线时间挑选，与热门区去重；没有合适上新则隐藏。新增榜单中的作品不算新主题 |
| 日常与工具 | 每日记录有紧凑快捷入口，完整能力在记录页；评分查询、猜电影提供可见入口，亦可在发现页找到。游戏玩法只显示实际开放项 |
| 广告 | 首期最多复用一个原有信息流广告位，放在完整热门模块之后；避开搜索、继续操作和首排内容。回归验证收益和转化，不先增加广告数量 |

首页不默认铺开个人置顶列表。现有置顶迁到记录页“常用”，首页通过继续卡解决高频回访，避免重现一长串模块。

### 3.3 新老用户和异常体验

- 新用户：搜索 → 热门主题 → 上新；首个有效动作应在首页点击主题后直接进入可标记页面。
- 老用户：搜索 → 继续标记 → 热门主题；不因返回首页重复跳回顶部或触发全屏加载。
- 外部分享进入：保持直达原主题，记录完成后可选择回首页或查看记录，不强制绕首页。
- 无网 / 人数服务失败：使用最近有效快照，页面仍可浏览；超过约定有效期后隐藏人数。没有可靠排行时使用“精选主题”兜底，不给未知数据标成 0 人。
- 热度更新不在用户滚动中插卡或换位置；本次页面会话保持快照，下一次进入或主动刷新再应用新版。

## 4. 热门内容如何选择

### 4.1 首期：基于现有数据，保持可解释

热门候选先限定为可正常进入且有可用内容的主题清单：电影、剧集、动漫、读书、旅行。每日记录、评分查询、猜电影和育儿评估属于不同任务，其核心行为不同，分别在快捷入口和发现的工具区域呈现，不与清单混排一张人数榜。

首期人数定义为：当前有效主题内容中，至少有一条有效标记的独立用户数。同一人在同一主题最多计 1 人，多条批量标记不增加人数；排除无效身份、测试数据与已删除标记。包含同步标记时，用“已有 N 人标记本榜作品”等准确说明，不宣称“主动参与”或“累计参与”。

展示和排序分开：排序用真实整数；较小人数显示真实值，零人数可不展示人数文案；较大人数才格式化为约数。停止人为加 100；估算与失败数据不进入热度榜。全局人数在服务端计算并只下发聚合值，核对访问权限不会让客户端仅统计到当前用户。

首页选取规则：

1. 所有合格清单按真实人数降序；同分按稳定的上线时间、主题 ID 决定顺序。
2. 依次取 6 张，同一一级内容领域最多 3 张，剩余从其他有可靠数据的领域补齐；不足时逐步放宽限制，再不足就少展示。
3. 首页标题使用“大家都在标记”，不展示连续名次；这是兼顾多样性的精选。发现页“热门排序”提供完整纯人数顺序，不套用首页配额。
4. 首页最近上新占独立 2 席，建议新主题曝光窗口为上线后 14 天；按上线时间、运营质量筛选去重。14 天为初始运营参数，后续用数据调整。
5. 育儿等工具保留明确入口；可在后续使用量足够时设置独立工具推荐，避免因为未进清单池就无法被发现。

### 4.2 后续：升级为近期主动参与热度

补充「用户主动在主题内成功标记 / 修改」的服务端行为事件，记录来源主题、时间与动作结果；跨榜同步只更新个人状态，不生成目标主题的主动参与事件。记录每日的主题去重人数，建议第二期以最近 7 天主动参与人数为主排序，近 30 天参与人数作为同分依据。

只有数据覆盖完整 7 天且口径稳定后才显示“本周热门”；“上升”标识需有完整的前后两个对比窗口，并设最低样本门槛。不能用旧标记快照的 marked_at 直接推断近期主动参与，因为同步也会更新时间。

累计人数用于社会证明，近期人数用于新鲜度，新上区用于冷启动。首期不引入难以解释的多权重算法；曝光机会不均的问题通过固定探索席位、曝光统计和对照试验逐步校正。

## 5. 发现页：承接完整信息架构

页面顺序：搜索 → 一级领域 → 必要的二级标签 → 排序 → 主题结果。工具与玩法提供独立可切换入口，搜索结果按“主题清单 / 工具与玩法”分组，空结果再推荐许愿。

| 层级 | 建议维度 | 例子 |
|---|---|---|
| 一级 | 内容领域 | 全部、电影、剧集、动漫、读书、旅行 |
| 二级 | 依领域变化 | 电影：评分榜、奖项、类型、导演 / 系列；旅行：景区、博物馆、省份、城市 |
| 标签 | 来源、地区、作者等，可多值 | 豆瓣、IMDb、奥斯卡、金棕榈、日剧、悬疑、东野圭吾 |
| 独立入口 | 工具与玩法 | 电影评分、猜电影、育儿评估、每日记录入口 |

将奥斯卡归入电影的奖项 / 来源标签，不继续作为与电影并列的一级领域。豆瓣同理作为来源和策划专题。动漫内容允许多标签检索，但“全部”结果按主题 ID 去重。育儿评估放在工具中；未来出现多项独立育儿内容后，再评估升级为内容领域。

发现默认使用热门排序，支持最新排序；有搜索词时优先匹配相关度，热度用于同等相关结果排序，避免搜具体名称却排在无关高热内容后面。保留现有封面 / 列表切换、搜索别名与个人展示偏好。

“许愿新榜单”从常驻大卡缩为搜索空结果和页面末尾入口；我的页保留固定入口。不要让许愿比已有结果更突出。

## 6. 记录与我的：回访和长期资产

记录首期自上而下：

1. **常用**：迁移现有个人置顶，保留原顺序；可同时固定主题和每日记录入口。
2. **我的主题**：按最近主动使用排序，显示已看 / 已读 / 去过进度和待办数量；直接进入原列表。跨榜同步产生但未主动进入的主题不自动挤满此区，仍可在发现中查看同步进度。
3. **每日记录**：电影、读书、运动、喝水四个入口，接已有日历、时间轴、统计和海报页，首期不重做统一时间轴。

历史数据若没有可靠的来源主题，不能还原用户曾主动进入哪些主题。首期只将用户置顶及改版后明确产生的访问 / 操作历史用于“常用 / 最近”，另设“有标记的主题”供查询，并提示可能包含同步结果。

不要直接把多个榜单的标记数相加成“看过多少部电影”。跨榜作品身份未完全统一前，个人汇总展示“参与主题数”等明确口径，作品总数后续基于可靠作品 ID 去重再上。

我的首期承接个人资料、外观、已有订阅设置、许愿与反馈、关于以及已有权益信息；点击头像进入资料编辑，退出操作放到设置。保留无需填写头像昵称即可浏览的体验。订阅仍由用户主动设置，不因为切换标签反复弹授权。

未来自建片单 / 书单落在记录页；公开清单经过质量与隐私流程后进入发现。年度回顾由记录数据生成，个人主页设置放我的。这样功能扩展无需新增底部标签。

## 7. 实施建议与兼容性

### 7.1 页面与路由

建议保留 `pages/category/category` 作为新首页路径，以兼容已有分享与“回首页”路径；新增发现、记录、我的三个根页面。现有电影、书单、旅行、每日记录、海报和游戏页继续作为二级业务页。

使用原生 tabBar 承载四个一级页。二级详情页保留返回和业务操作栏，不在所有页面强行绘制底部导航。首页与发现之间用一次性状态传递搜索词、分类与排序；读取后清理，普通点标签时保留该页原有筛选和滚动状态。

微信官方 API 类型定义明确：`wx.switchTab` 目标必须为已注册的 tabBar 页，URL 不能带参数。因此跨标签筛选不能照搬 `?category=movie`；迁移时需审计所有返回首页、navigator 与重定向路径。来源：[微信小程序官方 API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts)。

### 7.2 数据与性能

- 抽取共享主题目录，合并本地兜底配置与云端注册表；统一 cardId、路由 theme、统计 theme 的映射。首页和发现共用，不复制第二份硬编码清单。
- 建议目录新增领域、标签、上线时间、可推荐状态；统计独立存储真实人数、统计口径、生成时间、有效状态。沿用既有封面缓存和颜色。
- 服务端定时生成热度快照，初始每天刷新一次；前端一次读取，不再为首页并发扫描几十个内容集合。统计故障保留上次成功快照。
- 第一屏不等待身份、完整个人记录或全部封面。内容骨架和缓存先展示，个人摘要独立加载；底部页按进入时加载。
- 个人进度提交成功后更新摘要；保留收藏 / 置顶、主题外观、封面 / 列表偏好，不静默重置。
- 已有云端新主题必须同时进入发现目录和统计候选池；不能只覆盖本地硬编码主题。

## 8. 分期与验收

| 阶段 | 交付 | 发布条件 |
|---|---|---|
| P0 数据基础 | 真实人数快照、主题映射、异常兜底、主动行为和来源埋点 | 核验全部开放主题；明确同步口径；统计不依赖当前访问者权限 |
| P1 本次改版 | 四标签、新首页、发现目录、轻量记录页、我的页 | 四页都有可用内容；老分享链接、置顶、主题外观兼容 |
| P2 数据迭代 | 近期热榜、兴趣排序、记录摘要、热门推荐优化 | 数据窗口完整；转化与曝光可归因；有对照评估 |
| P3 产品扩展 | 自建清单、跨榜作品库、年度回顾、公开优质清单 | 作品去重和个人数据模型稳定，需求验证通过 |

验收路径至少覆盖：新用户从首页进入并完成首次标记；老用户继续主题和每日记录；发现筛选返回不丢状态；老分享链接直达；跨榜同步不误计主动参与；新增云端主题可发现；未完善资料、零记录、统计失败、封面失败、窄屏、大字体及 iOS / Android 底部安全区域。

本次核心指标定义为「进入首页的用户中，同次会话成功完成至少一次有效标记或每日记录的比例」，点击不算成功；取消、失败和同步扇出不重复计数。辅助看热门曝光到点击、点击到有效操作、记录页继续使用率、首次有效操作耗时、7 日回访和新主题有效参与覆盖。

埋点补充入口来源、模块、位置、主题 ID、排序版本和成功结果；卡片实际进入视口才计曝光。现有 theme_open / mark / daily_checkin 可扩展衔接，并核对小程序后台已注册对应事件字段。

上线前收集至少一周可比基线；优先按用户固定分组做对照，样本不足时只报告趋势，不宣称因果提升。首期不虚设增长承诺。护栏观察首屏加载、保存失败、崩溃、回访和广告收益；若内容转化下降，先调整模块、排序和广告位置。数据或推荐故障可降级为精选快照；tabBar 属于版本结构，不能承诺仅靠远程配置恢复旧导航，结构回退需要客户端版本处理。

## 9. 本版决策摘要

四个稳定入口；首页优先热门与继续操作；发现保留全部内容；记录沉淀个人使用；我的管理偏好与服务。先把真实人数用于可解释的热门精选，再用主动行为数据升级近期热榜。新主题通过独立上新席位获得机会，领域扩展和未来自建清单均能沿现有架构落位。
