# 首页与底部导航改造：上线说明

日期：2026-10-12。当前状态：本地修订及测试完成；用户已部署云函数并提供有效统计结果及分项错误日志。最新的新旧查询对比入口仍需用户重新部署，本次未上传小程序版本。

## 已实现

- 原生四标签：首页、发现、记录、我的。首页沿用 `pages/category/category`，已有分享链接继续可用。
- 首页恢复旧版 Hero 的主题色背景、装饰圆和圆角底边，标题使用 42rpx 常规字重，搜索放在 Hero 内的白色卡片中，收紧搜索框与上下间距。随后依次是每日标记、最新上线（4 项）、最受欢迎（前 10 项）、评分查询和电影填词玩法。去除首页副标题、继续标记与每日标记右侧的“我的记录”，首页不再请求个人进度汇总。广告位仍在完整热门模块后。
- `wishFrom` 许愿来源显示在封面图内，榜单名称统一单行，超长名称可左右滑动查看（包含发现页和记录页）。移除“探索这份清单”。首页可直接切换樱花粉、暖金、橄榄绿、暖沙，搜索区、每日入口、标题、人数与排名随主题变化；原生底部导航的选中图标和文字同步换色。修复樱花粉在重启后被重置为绿色。
- 发现页保留搜索别名、快捷词、封面 / 列表偏好，新增热门 / 最新排序；奥斯卡归入电影，工具含每日记录、评分、育儿与游戏。
- 记录页保留原 `categoryPinnedIds` 顺序，支持管理常用；汇总云端已有标记进度。最近使用明确标为本机记录。
- 我的页复用头像昵称编辑、主题外观、会员信息、许愿、反馈；增加系统订阅设置与关于入口。
- 新云函数 `getThemeHub` 提供公共热度快照和基于调用者微信身份的个人进度，不接受客户端指定他人 openid。
- 热度为有效标记的真实去重人数，包含跨榜同步；按人数降序取前 10，无领域配额，每次更新统计后重排。未知统计不参与人气排名；人数为 0 的有效统计可以参与。完全没有有效统计时，显示暂不可用与浏览入口。
- 人气统计首次请求失败后，切换标签返回首页或发现会重新尝试；首页错误区提供“重新加载”，下拉刷新也强制重新取数。空缓存、全失败缓存或只有空榜单的缓存不再抑制后续请求。加载期间展示读取提示，部分统计失败不会阻断其他榜单的排名。

## 首次部署顺序

1. 在微信开发者工具内，右键 `cloudfunctions/getThemeHub`，选择上传并部署（云端安装依赖）。确认超时为 60 秒，安装 `config.json` 的每日定时触发器。
2. 确认现有 `theme_registry` 可由云函数读取。`theme_hub_cache` 只存公共人数快照，可由函数首次创建；若环境限制自动建集合，在控制台创建该集合并仅允许云函数写入。私有标记和 openid 不写入快照。
3. 调用 `getThemeHub`，参数 `{"action":"stats"}`，核对 `success`、各行 `valid`、`users`、`total` 和生成时间。样本核对电影、图书、旅行及一项云端新增主题。可用环境变量 `EXCLUDED_OPENIDS`（英文逗号分隔）排除测试账号；变量内容不输出到客户端。
4. 通过小程序真实用户调用 `{"action":"summary"}`，核对已有标记与榜单内数量一致。控制台无微信用户上下文时会返回身份不可用，这是预期行为。
5. 在小程序后台注册 `hub_exposure` / `hub_click` 事件，参数 `page`、`theme`、`module`、`version` 均为字符串。曝光由卡片进入视口触发，不按下载目录或渲染全部结果计数。
6. 部署 `cloudfunctions/wishLike`（记录页「期待上线」计数，超时 10 秒）。集合 `WishLikes` 由函数首次写入时自动创建；若环境限制自动建集合，在控制台手建并仅允许云函数读写。控制台测试 `{"action":"get"}` 应返回 `{"success":true,"total":0}`。
7. 在小程序后台注册 `hub_favorite`（参数 `theme` 字符串、`on` 整型、`version` 字符串）；`records_wish_like`（`count` 整型）现在每人每天只报一次。
8. 编译并真机预览，验收通过后再上传、审核和发布。

截至本次检查，本机开发者工具 CLI 提示服务端口关闭，未执行自动部署或模拟器调试。需要使用开发者工具界面完成上述操作，或由用户自行开启 CLI 服务端口后再自动验证。

## 人气统计排查

用户返回的统计快照包含有效人数和作品数，可直接展示热门榜单；其中 `douban_movies` 和 `imdb_movies` 的 `valid:false` 仅影响这两项，不应让整个首页显示不可用。前端重新编译后，可在首页下拉刷新或点击“重新加载”。

若继续排查这两项，用户自行重新部署 `getThemeHub` 的最新代码，并在云端测试输入 `{"Type":"Timer"}`，触发重新统计而不复用一天内的公共快照。查看 `[getThemeHub] membership scan failed` 或 `[getThemeHub] user count failed` 日志，可分别定位榜单作品读取失败和人数聚合失败。客户端仅记录云调用错误码，不输出用户身份。

用户日志已确认这两项为人数聚合阶段数据库超时。旧版在聚合失败后用标记条数除以 3 估算人数，展示时还会加 100；新版新增有效状态和用户身份筛选。先用 `{"action":"compareStats"}` 对比同环境、同电影 ID 下两种查询的耗时和错误，再决定优化方案。该诊断不修改统计快照。详见 [人气统计新旧差异-2026-10-12.md](人气统计新旧差异-2026-10-12.md)。

## 上新元数据

云端注册表增加 `publishedAt`（或 `launchedAt`），使用明确时区的 ISO 日期字符串。只在实际上线时写入，不能用编辑时间冒充上线时间。

首页“最新上线”取最近 4 项，不限 14 天，可与热门重复；优先按真实上线日期降序，未来上线、已隐藏、工具和已知空榜单不进入。历史榜单缺少日期时按现有目录顺序补位，不伪造上线日期。上线前建议补齐注册表中的真实日期，以保证这 4 项严格代表最近上线的榜单。发现的最新排序也将无日期主题放在有日期主题之后。

## 真机验收路径

- 新用户从首页进入主题、标记、返回；每日主题位于搜索下方，最新 4 卡、热门前 10 排名正确，图片失败不阻断进入。
- 首页“更多榜单”进入发现的热门排序，“查看全部”进入最新排序；搜索作者 / 奖项 / 类型；切换标签后保留原筛选与滚动位置。
- 老用户常用順序、主题色、列表偏好不丢；修改标记后返回记录页刷新进度；每日记录仍可添加并生成海报。
- 外部分享直达旧页面，回首页进入首页标签；不强制绕首页。
- 断网、统计服务失败、部分集合缺失时，不伪装零记录或零参与者；点击重试可恢复。
- iOS / Android、小屏 / 大字模式、键盘弹出、底部安全区、资料编辑与常用管理弹窗。
- 广告和免广告会员状态保持原逻辑，记录 / 我的 / 发现不额外加载首页广告位。
