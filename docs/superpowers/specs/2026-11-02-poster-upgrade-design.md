# 海报质感升级 · 设计文档

- 日期：2026-11-02
- 分支：`feature/poster-upgrade`
- 范围：榜单海报、每日电影范围海报、每日电影单部海报，换版式，不只是换配色
- 已定稿的视觉基准：`docs/superpowers/mockups/refined.html`（1080×1440 精修稿，三张）
- 版式草图（只看结构，不看精致度）：`docs/superpowers/mockups/poster-directions.html`
- 本地预览：`node docs/superpowers/mockups/serve.cjs` → http://localhost:5178/refined.html（封面图不进仓库，先跑 `node docs/superpowers/mockups/fetch-covers.cjs` 下载）

## 1. 为什么做

海报是这个小程序的传播出口，也是收入来源：激励视频收入的大头来自「保存海报」，豆瓣 TOP250 海报页一页就占了激励收入的 86%。但现状有两个问题：

- 打开海报页的人里，约 78% 没有保存（2026-08 统计）。
- 日均只有约 9 人分享，会话来源只占访问量的 3%（2026-10 统计）。

现在的海报是「清单」：三套背景渐变，加上统一的封面网格或文字胶囊，只能换配色。这一轮要换的是版式本身，让海报**一眼就想存、就想发**。

## 2. 视觉原则（和用户反复对过，已定）

这几条是前三版样稿被否掉后定下来的，后面每个版式都要遵守：

1. **颜色交给真实封面。** 底色只有三种：纯白 `#FFFFFF`、浅灰 `#F4F5F7`、**封面取色的淡色模糊底**（把封面糊开后叠 50% 白）。不再用整块的彩色底，也不用复古的牛皮纸、暗场色。
2. **字只用黑和灰。** 墨色 `#16181D` / 次要 `#6B7079` / 弱 `#A3A8B0` / 发丝线 `#E6E8EC`。
3. **全图只有一个亮色**：珊瑚橙 `#FF5B3A`，只用在星级、百分比、想看这类「要被看到」的地方。
4. **按成品尺寸设计**：基准 1080×1440（3:4，小红书首图比例），页边距 64~72px。
5. **固定字号阶梯**：300（主数字）/ 96 / 72 / 64 / 34 / 28 / 22 / 20。每张海报只有一个视觉焦点（一个大数字，或一张大封面）。
6. **数字单独用 Inter**（拉丁字体，等宽数字）；中文用系统字体（iOS 是苹方）。
7. **封面统一处理**：8px 圆角 + 1px `rgba(0,0,0,.06)` 描边 + 很淡的投影。
8. **署名统一**：底部居中「● 使用小程序「标记吧」生成」。不出现二维码、链接、微信字样（推广合规）。

样稿用的是 Google Fonts 的思源黑体，Windows 浏览器里看着和手机上的效果接近。真机以 iOS 苹方为准。

## 3. 版式矩阵

六种版式，每类海报只用适合它的那几种。★ = 这类海报的新默认版式。

| 版式 | 榜单 | 每日电影 · 范围 | 每日电影 · 单部 | 结构要点 |
|---|---|---|---|---|
| 杂志封面 | ★ | ✓ | ✓ | 刊头 + 一个 300px 大数字或一张整幅封面 + 发丝线栅格 |
| 日程清单 | — | ★（月度默认；年度默认杂志封面） | — | 浅灰底 + 白卡片，按日期分组；长图，高度随条数 |
| 电影票根 | — | ✓（票夹） | ★ | 白票 + 镂空半圆缺口 + 齿孔线 + 条形码；底为封面取色模糊 |
| 拍立得 | — | ✓（≤9 部） | ✓ | 白边相纸错落贴；底为封面取色模糊 |
| 胶片条 | ✓ | ✓ | — | 黑胶片 + 齿孔 + 帧号，白底 |
| 电子小票 | ✓ | ✓ | ✓ | 锯齿边白小票 + 等宽字 + 条形码；长图 |

**原版式保留为「经典」**，放在版式选项的最后一个，不删：榜单的海报墙和文字胶囊/列表，每日电影的整体、按月份、按评分、日历，以及单部封面海报，都继续通过现有的 `moviePosterDrawer.js` 绘制、原样不动。先上线、看数据，确认新版式的保存率不低于经典，再考虑下线。

### 3.1 每个版式的数量规则

| 版式 | 数量多了怎么办 |
|---|---|
| 杂志封面 · 榜单 | 点阵画全榜（N 个点，列数随 N 变化：N≤100 → 20 列，≤300 → 50 列，更多 → 按宽度算）；封面墙最多 24 张（8×3），不足 24 张就按行收起，0 张走空态 |
| 杂志封面 · 范围 | 主图 = 范围内星级最高的那部（同分取最早）；下面一排缩略封面，最多 22 张 |
| 日程清单 | 长图，最多 60 条；超过就画前 60 条，加一行「还有 N 部」 |
| 拍立得 · 范围 | 最多 9 张（3×3），选星级最高的 9 部；标题统计仍按全部 |
| 票根 · 范围（票夹） | 长图，每部一张横票，最多 40 张 |
| 胶片条 · 榜单 | 只放看过的，每条 9 帧，最多 6 条（54 帧），超出加「另 N 部」 |
| 胶片条 · 范围 | 竖胶片 + 右侧片单，最多 12 帧，片单最多 20 行 |
| 电子小票 | 长图，最多 300 行，超出加「… 另 N 部」 |

长图统一宽 1080，高度上限 6000（面积约 650 万像素，远低于 iOS canvas 的 1677 万像素上限）。

## 4. 数据来源（每个字段都要有出处）

原则：**海报上的每个数字和每段文字，都必须能指到库里的某个字段**。查不到的不画，不编造，不估算。

### 4.1 榜单海报

| 画面元素 | 来源 | 备注 |
|---|---|---|
| 榜单名 | `genericThemeConfig` 的 `title`；豆瓣 TOP250 写死 | |
| 已看 / 想看 / 未看 / 总数 | `Marks.status`（`watched` / `wish`）× 榜单条目数 | 与列表页同一口径（`dataLoader.processMarks`） |
| 完成百分比 | 已看 ÷ 总数 | |
| 点阵顺序 | 榜单条目的 `rank` | |
| 封面墙「最近标记的 24 部」 | 按 `Marks.marked_at` 倒序 | **是标记时间，不是看片时间**，文案只能写「最近标记」 |
| 胶片帧号 `#001` | `rank` | |
| 刊号「VOL.2026 · NO.11」 | 生成海报当天的年和月 | 这是出刊日期，不代表数据范围 |

### 4.2 每日电影（范围 + 单部）

| 画面元素 | 来源 | 备注 |
|---|---|---|
| 片名 / 年份 / 导演 / 类型 / 封面 | `DailyLogs.entries[].meta`：`title` `year` `director` `genres` `poster` | 封面走现有换链（云存储） |
| 观影日期、星期 | 条目所在 `DailyLogs.date` | |
| 我的星级 | `meta.rating`（1~5） | 未评分不画星，不当 0 星 |
| 心情 / 短评 | `meta.mood` / `meta.note` | 没写就整块不画 |
| 平台评分（豆瓣 / IMDb / 烂番茄） | `meta.platform` | 是**记录当时**的快照；缺哪个就少一栏；「隐藏平台评分」开关保留 |
| N 部 / 观影日 / 平均星级 | 范围内条目，按「部」去重（与日历页同一口径）；平均只算有星级的 | 平均星级显示 5 星制一位小数 |
| 「我记录的第 37 部」 | 该用户截至这条记录的条目总数（`getAll` 已拉全量） | 措辞必须是「记录的第 N 部」，不能写成「今年第 N 部」 |
| 主图「本月最爱」（年度为「最爱」） | 范围内 `meta.rating` 最高的一部，同分取最早 | 全都没评分时，主图取范围内第一部，文案改成「本月第一部」/「第一部」 |

**不能显示的：**
- **观影时刻**（样稿里的 20:10 这类）：条目的 `ts` 是记录时间，不是看片时间，库里没有看片时刻 → 删掉。
- **「年度」字样，在数据不满一年时不能用。** 用户最早的记录只有几个月：年度范围的标题写「2026 · 共 N 个月有记录」，不写「年度总结」。

### 4.3 封面取色的模糊底

来源就是封面图本身：在手机上把封面画到一张很小的离屏 canvas 上（约 24×32），再放大铺满整张海报，这一步就有模糊效果；然后叠 50% 白。不需要新数据。

豆瓣详情接口里有 `color_scheme`（`primary_color_light/dark`），但颜色偏暗、偏沉，也没存进库。这一轮不用它。

### 4.4 这一轮明确不做（没有数据来源）

- 观影人格标签、「超过 X% 的用户」：没有可信的计算口径和数据来源。
- 年度总结专题：等「从豆瓣导入」积累了全量数据之后另开一份设计，形式和内容都要和豆瓣官方的年度报告明显不同。

## 5. 技术方案

### 5.1 模块拆分（新增 `utils/poster/`）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `tokens.js` | 颜色、字号阶梯、间距、圆角，全部按 1080 基准 | 无 |
| `kit.js` | canvas 绘图原语：带字距的文字（逐字画，小程序 canvas 不保证支持 `letterSpacing`）、省略与换行、圆角矩形、封面（圆角 + 描边 + 投影）、星形 path、虚线、票根外轮廓 path（**用 path 画出镂空缺口，导出时缺口里是背景**）、锯齿边、条形码、点阵 | `tokens` |
| `fonts.js` | 用 `wx.loadFontFace`（`scopes: ['native']`）从云存储加载 Inter 子集（只含数字和拉丁字母，约 30KB；字体文件经 `uploadStaticAssets` 云函数上传，控制台手传的文件读不到）；加载失败或超时 1.5 秒就回退系统字体 | 无 |
| `tint.js` | 封面 → 模糊底（缩小再放大）+ 白色蒙层 | `kit` |
| `model.js` | 三个适配器，把各页数据整理成统一的 `PosterModel`：`fromRanking` / `fromDailyRange` / `fromDailySingle`。第 4 节的口径（去重、平均、第 N 部、最近标记）只在这里实现一次 | 无 |
| `layouts/magazine.js` `agenda.js` `ticket.js` `polaroid.js` `film.js` `receipt.js` | 每个版式一个文件，统一接口：`supports(kind)`、`measure(model) → {width,height}`、`draw(ctx, model, covers, opts)` | `kit` `tokens` `tint` |
| `index.js` | 版式注册表：每类海报有哪些版式、默认哪个、显示名 | `layouts/*` |

`measure` 和 `model.js` 都是纯函数，能用 node 直接测；`draw` 只管画。

**词表沿用 `MOVIE_VOCAB` 的思路**：「部 / 观影」这些文案从 model 传进来，版式代码里不写死。每日读书以后可以零复制接入，但这一轮只给每日电影开放。

### 5.2 页面改动

- `pages/daily/movie/share`：选项面板的「版式」改为新版式 + 「经典」。选中经典时，下面展开原来的四个子版式（整体 / 按月份 / 按评分 / 日历），逻辑不变。单部模式加一行「版式」。每类海报记住用户上次选的版式（storage key 用 `moviePosterStyle` 这一类前缀）。
- `pages/douban/share`、`pages/genericList/share`：现在是 DOM 画预览、隐藏的 canvas 负责导出，每个版式都要写两遍。改成**直接把 canvas 当预览**：每日电影分享页已经这么做了，canvas 是原生组件，没法用 opacity 隐藏。经典版式继续走原来的绘制代码，新版式走 `utils/poster`。列表页的两个入口（海报 / 文字）保留：海报入口默认杂志封面，文字入口默认电子小票。
- 封面加载继续用 `utils/posterCovers.js`（`ensureCoverNodes`，6 张并发）。
- 导出继续用 jpg 0.92；保存继续走 `rewardedSaveGate`，不改动广告逻辑。
- `pages/daily/read/share` 这一轮不动。

### 5.3 埋点

`poster_save` 和 `poster_view` 加一个字符串属性 `layout`（取值如 `magazine` / `agenda` / `classic`）。**上线前要先在小程序后台「上报管理」里给这两个事件加上这个属性**，否则数据报不上来。这样才能按版式比较保存率。

## 6. 分期

每个版式都按同一个流程：先出 1080 精修 HTML 稿（和 `refined.html` 同一个标准）→ 用户确认 → 写 canvas → 真机核对。

| 期 | 内容 | 完成标准 |
|---|---|---|
| P0 基础 | `tokens` `kit` `fonts` `tint` `model` + 版式注册表；在一个调试页上把 `refined.html` 的票根画出来 | 真机验证三个技术风险（见第 7 节），iOS 和安卓各一台 |
| P1 单部 | 票根★ / 杂志封面 / 拍立得 / 电子小票 + 经典 | 单部海报出图小于 1.5 秒 |
| P2 范围 | 日程清单★ / 杂志封面 / 拍立得 / 胶片条 / 票夹 / 电子小票 + 经典 | 30 部封面的月度海报出图小于 3 秒 |
| P3 榜单 | 杂志封面★ / 胶片条 / 电子小票 + 经典；先豆瓣 TOP250，再通用榜单页 | 两个分享页都改成 canvas 预览，经典版式输出和现在一致 |

先做单部，再做范围，最后做榜单：单部最小，适合把基础模块磨好；榜单页是收入大头，放在最后，而且新默认版式要灰度上线（见第 8 节）。

## 7. 技术风险（P0 必须先在真机上验证）

1. **Inter 在 canvas 2d 里能不能生效。** `loadFontFace` 加 `scopes: ['native']` 理论上可以，但各基础库版本表现不一。不生效就回退系统数字字体，版式不能依赖 Inter 才成立。
2. **缩小再放大的模糊效果**，在 iOS 和安卓上的平滑程度（`imageSmoothingQuality`）。效果不够就多缩放一级。
3. **票根缺口用 path 镂空后导出 jpg**：缺口里应该是背景色（模糊底），不能是黑色或白色。
4. 安卓机上没有苹方，中文用系统黑体，要确认字重 700/900 的显示效果，必要时把标题字重降到 700。

## 8. 上线与验证

- **测试**：`tools/test-poster-model.cjs`（口径：去重、平均星级、第 N 部、最近标记排序、空数据），`tools/test-poster-measure.cjs`（各版式在 0 / 1 / 12 / 60 / 300 条时的尺寸和上限）。用 `node --test` 跑。
- **视觉核对**：每个版式在开发者工具和真机上各出一张，和 1080 精修稿并排对比。
- **灰度**：豆瓣 TOP250 海报页的默认版式按 `grayBucket` 50% 灰度切到杂志封面，跑两周，比较两组的 `poster_save ÷ poster_view`。每日电影页直接切默认，因为用户量小，风险也低。
- **成功标准**：豆瓣海报页的保存率不下降（这一页的收入不能掉）；新版式的保存率高于经典；日均分享人数从 9 人往上走（同时受其他改动影响，只作参考）。

## 9. 不做

- 年度观影总结专题（以后单独写设计文档）
- 人格标签、用户百分位
- 每日读书、书单类海报（模块支持词表，以后接）
- 评分查询详情页（`pages/movie-search/detail`）的保存海报
- 二维码、链接、引流文案
