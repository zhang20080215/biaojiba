# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

XiaoBiaoji (标记吧) is a WeChat Mini Program with several feature areas:
1. **Movie / book tracking** — Douban Top 250 (movies + books), IMDb Top 250, Oscar Best Pictures (`oscar`), Oscar Best Animated Feature (`oscarAnime`, 最佳动画长篇), Oscar Best Cinematography (`oscarCinematography`, 最佳摄影), 票房榜 (boxoffice), WeChat Reading Top 200, plus themes kept in source but pack-excluded for now (annual / chinese / chinese-awards). All share the same list+poster pattern, swap data source; only `douban` keeps its own page set, everything else renders through the shared `pages/genericList` / `pages/genericBookList` / `pages/scenic` sets (see Movie / Book Theme Pattern). Most movie ranking/award themes (18 as of this writing — `oscarCinematography`/`rtHorror`/`rtWar`/`rtAnimation`/`palmeDor`/`oscarScreenplay`/`letterboxd500`/`oscarForeign`/`rtAction`/`oscarDirector`/`oscarVFX`/`oscarActor`/`oscarActress`/`doubanTvCn`/`doubanTvForeign`/`doubanTvAnime`/`arthouse`/`sightsound`) run on the generic `enrichThemeMovies`/`getThemeMovies` pipeline and share one page set, `pages/genericList`. Book award/ranking themes (starting with 茅盾文学奖, `maodun`) run on the equivalent book pipeline, `enrichThemeBooks`/`getThemeBooks` + shared page set `pages/genericBookList`. See Generic Theme Pipelines.
2. **Movie rating search** (`pages/movie-search`, 全平台电影评分查询) — search any movie by title, aggregate 豆瓣 + IMDb + 烂番茄 (Tomatometer critic + Popcornmeter audience) scores. Independent data path (own collections + cloud functions), separate from the Top-N tracking pattern.
3. **Child growth assessment** — 0~7岁发育评估 based on WS/T 423-2022 national standard, with precise percentile calculation and shareable report posters.
4. **Daily check-in** — Theme-driven daily tracker. Live themes: **每日喝水** (`water`, shared `pages/daily/index` + `pages/daily/stats` page set) plus three richer themes with their own page sets — **每日电影** (`movie`), **每日读书** (`read`), **每日运动** (`sport`) — **每日步数** (`steps`, 微信运动自动同步) and **每日早睡** (`sleep`, 手动记录、主攻早睡) — the *metric-kind* themes on the shared `pages/daily/metric/*` set (branch `feature/daily-steps`, pending deployment). See Daily Check-In Theme.
5. **Subscription push** — WeChat subscribe-message framework for TOP250 new-entry alerts and daily reminders. See Subscription & Push.
6. **Movie guessing game** (`pages/guess/`, 每日猜电影) — daily puzzle in three modes over one film pool: 交叉填格 (3×3 grid, moviegrid.io-style), 纵横填字 (7×7 crossword built from five film titles) and 线索猜片 (9 clues, one answer). Runs entirely on Douban-derived data already in the repo's own collections — no TMDB. See Movie Guessing Game.
7. **Custom lists** (`pages/customList/`, 自建影单·书单) — each user builds their own 影单 / 书单 (1 each by default, ≤200 items), adding from existing rankings or by Douban title search. See Custom Lists.

Built on WeChat Cloud (serverless cloud functions + cloud database).

## Architecture

**Navigation update (2026-10-12, pending deployment):** Four native tabs: existing `pages/category/category` = home; `pages/discover/index` = complete catalog; `pages/records/index` = pinned/recent themes and personal progress; `pages/profile/index` = profile/preferences/services. Their shared page factory is `utils/hubPage.js`, local catalog is `utils/themeCatalog.js`, view is `templates/hub.wxml` (each wrapper must both import its templates and include its body). `utils/hubModel.js` owns pure ranking/filter rules; `utils/hubStore.js` owns cache and one-shot cross-tab intents. New `getThemeHub` provides real distinct marked-user counts and caller-scoped progress; deploy it before releasing the client. The old client-side count inflation and estimate fallback were removed. Existing `categoryPinnedIds` and `categoryViewMode` storage remain compatible. Older sections below that mention adding rows to category.js now refer to themeCatalog.js / hubPage.js; register a new local list in `getThemeHub/catalog.json` too (tested). See `docs/首页导航改造-上线说明.md` for rollout and tests.

**「记录」tab 走云端开关（2026-10-27，因 1.0.56 审核以「记录点击无响应」驳回）：** 底部 tab 改成自定义组件 `custom-tab-bar/`（`app.json` `tabBar.custom: true`，`list` 仍须保留四项，`switchTab` 靠它），「记录」是否露出读 `adConfig.shouldShowRecordsTab()` ← 云端 `app_config`（`key: 'ad_config'` 那条）的 `showRecordsTab`，默认 false。**提审期间保持 false，过审上线后改 true**，用户下次进入即出现，不用发版。它只管 tab 露不露；页面本身是否还是「打磨中」蒙版仍由 `utils/hubFlags.js` 的 `recordsOpen` 决定，两者独立。原生 `setTabBarStyle/setTabBarItem` 对自定义 tab 无效，主题色/选中态由 `hubStore.applyTabStyle(theme, page, kind)` 推给 `page.getTabBar().sync()`。**自定义 tab 栏画在页面之上，页面里的弹窗 z-index 再高也盖不住它**（2026-10-29 主题色面板、管理收藏面板的底部按钮被挡）：四个 tab 页的弹窗（`showThemePicker` / `showPinManager` / `showRequestModal` / `showAuthModal`）每次开关后都调 `hubPage._syncTabBar()`，任一开着就 `getTabBar().setHidden(true)`、全关了再放回；新增 tab 页弹窗要把它的开关加进 `_syncTabBar`。首页搜索行右边的按钮 2026-10-29 由「反馈」改成「客服」（`open-type="contact"`），意见反馈仍在「我的」菜单。

**Frontend:** WeChat Mini Program (WXML/WXSS/JS) with Canvas 2D API for poster generation.

**Backend:** WeChat Cloud Functions (Node.js + `wx-server-sdk`) in `cloudfunctions/`. Each function is independently deployed with its own `package.json`.

**Entry point:** `pages/category/category` — tab-filtered card grid (`全部/电影/剧集/奥斯卡/读书/旅行/育儿`), routes to all themes. **No cover image ships in the package** (the 10 `images/cover-*.jpg` were dropped in 2026-09, -250 KB): every ranking card takes its cover from `DYNAMIC_COVER_THEMES` (rank=1 doc of its collection; `top: true` excludes soft-deleted TOP-list docs, `latest: true` takes the newest 届 for the Oscar-style lists where rank = 届数), cached in `wx.storage` under `categoryDynCovers`; the three cards with no collection (每日电影/每日读书/评分查询) reference cloud-storage fileIDs under `category_covers/` (source jpgs in `tools/category-covers/`). Each theme row carries `brand: [soft, primary]` + `placeholderEmoji`/`placeholderText`; `_decorateThemes` derives the inline `tintStyle`/`coverStyle`, and the card wxml is one `<template name="theme-card">` with three cover branches (image → dynamicCover → gradient placeholder, which shows a CSS `.skeleton` shimmer while `coversLoading`). Add a theme = one row, no wxml/wxss branch.

### Movie / Book Theme Pattern
**Only `douban` (豆瓣电影 TOP250) still has its own page set** — `pages/douban/{list,share}` + `utils/doubanLoader.js`: it is the flagship page (subscription entry, `theme-gold/green/sand` colour classes, its own poster experiments), so it deliberately stays off the shared pages. Every other ranking theme renders through a shared page set driven by `?theme=`:
- movies → `pages/genericList/{list,share}` + `utils/genericThemeConfig.js` (incl. the old dedicated-collection themes `imdb` / `oscar` / `boxoffice` / `oscarAnime`, which keep their own collections + `fetch*` cloud functions and read through `getMoviesData`; the config rows carry `ratingLabel` (IMDB), `extraChips` (年份/全球票房), `useCache` (24h cache instead of force-refresh) for them)
- books → `pages/genericBookList/{list,share}` + `utils/genericBookThemeConfig.js` (incl. `douban_books` / `weread_books` — their rows **must** keep `source: 'douban'` / `'weread'`, that is what `getMoviesData` filters `BookMarks` on; `simplifyTitle` strips 版本括注 on posters)
- travel 打卡 (5A 景区 / 一级博物馆) → `pages/scenic/{list,share}` + `utils/travelThemeConfig.js`

The 2026-09 package-size pass folded `pages/{imdb,oscar,boxoffice,doubanBooks,weread,museum}` into those shared sets (~-600 KB). **Their `list` paths still exist as 3-file redirect stubs** (`Page({ onLoad(){ wx.redirectTo(...) } })`) because shared cards, 搜索直达 and 后台 landing paths point at them — keep the stubs registered in `app.json`; only the `share` paths were dropped. Analytics keys (`trackThemeOpen`/`trackMark`/`trackShare`) now use the theme id (`imdb`, `douban_books`, `museum`…) — the old dedicated pages used a mix (`doubanBooks`, `weread`).
- Cloud function `fetch{Theme}{Movies|Books}` — data scraping/enrichment, unchanged per theme
- Marks split by collection: movies → `Marks`, books → `BookMarks`; cloud function `batchUpdateBookMarks` mirrors `batchUpdateMarks`

**Data flow:** Pages → `utils/dataLoader.js` (24-hour client cache) → `getMoviesData`/`getThemeMovies`/`getThemeBooks` cloud function (routed by theme id) → Cloud DB collections (`movies`, `imdb_movies`, `oscar_movies`, `oscar_anime_movies`, `generic_theme_movies`, `douban_books`, `weread_books`, `generic_theme_books`, `Marks`, `BookMarks`)

**Douban TOP250 auto-refresh:** `fetchMovies` (timer-triggered; tolerant of the new cloud runtime `Type=Timer` event wrapper) re-scrapes Douban TOP250 daily into `movies`. Guards against scraper failures: writes are rejected if fewer than `MIN_ACCEPT_COUNT` (240) items are scraped. Tracks a version doc + soft-delete rollback doc, detects `_id` drift (same title, different `_id`), and emits `push_events` + `rank_history` entries consumed by the push framework.

### Generic Theme Pipelines

**Fast-onboarding a new curated-list theme (no new cloud function, no new page directory):** for a one-off ranking/list theme (user hands over a list, or a source to extract one from — not an auto-refreshed daily scrape), use one of the two generic pipelines below instead of copying a new `fetch{Theme}{Movies|Books}` function or a new page directory. Movies and books each have their own parallel pipeline (backend collection + cloud functions + shared page set + config file); a new theme is just a config-table row + a category.js card.

**Movies** (18 themes as of this writing — `oscarCinematography`/`rtHorror`/`rtWar`/`rtAnimation`/`palmeDor`/`oscarScreenplay`/`letterboxd500`/`oscarForeign`/`rtAction`/`oscarDirector`/`oscarVFX`/`oscarActor`/`oscarActress`/`doubanTvCn`/`doubanTvForeign`/`doubanTvAnime`/`arthouse`/`sightsound`):
- `cloudfunctions/enrichThemeMovies` — takes `{ theme, movieList: [{rank, year, title, originalTitle, ...extra}], idStrategy: 'rank'|'title-year', forceRefresh, startFrom }`, does the same Douban-search-match + cover-download-upload + resumable-batch-upsert logic as `fetchOscarAnimeMovies`, and writes into the **shared** `generic_theme_movies` collection (`_id` prefixed `${theme}_...`, discriminated by a `theme` field). Douban cover + rating only — no IMDb/OMDb (that path is per-movie daily-rate-limited, unsuitable for bulk seeding). **Title normalization:** after matching a `doubanId` it fetches the Douban rexxar detail and overwrites `title` with the mainland-standard (simplified) name, archiving the list's raw title into `sourceTitle` — 港台/繁体 source lists land as 简体 automatically; re-running the same raw list won't clobber corrected titles (the light-patch path skips `title` when it equals `sourceTitle`). `cloudfunctions/checkDoubanTitles` (`{theme, apply}` mode) audits/fixes titles for already-seeded themes; `cloudfunctions/checkThemeRankGaps` diagnoses missing/duplicate `rank` values.
- `cloudfunctions/getThemeMovies` — read-side counterpart, query-by-`theme` against `generic_theme_movies`, response shape matches `getMoviesData` (`{success, movies, marks, listVersion}`). Deliberately a **separate** function so existing themes' `getMoviesData` path is untouched.
- `utils/dataLoader.js`'s `GENERIC_THEMES` Set + `cloudFnForTheme(theme)` route a theme id to `getThemeMovies` vs `getMoviesData`; register a new theme id there.
- Frontend: **one shared page set**, `pages/genericList/{list,share}`, driven by `?theme=xxx` + `utils/genericThemeConfig.js` (`THEME_CONFIG` table: title/slogan/brand colors/`showEdition`/`editionField`/`orderDirection`). Marks reuse the plain `Marks` collection (no `source` discriminator needed — `_id`s are theme-prefixed and globally unique). Poster drawing (poster wall + text capsule/list styles) is inlined in `share.js`, no per-theme `PosterDrawer` module.
- `pages/category/category.js`'s `_countThemeUsers` `themeConfigs` entries support an optional `theme` key (`{ id, collection: 'generic_theme_movies', theme: 'xxx' }`); `DYNAMIC_COVER_THEMES` (dynamic card cover = theme's `rank:1` item's cover) also needs an entry.
- Onboarding a new theme = one `THEME_CONFIG` row + one `GENERIC_THEMES` entry + one `themeConfigs`/`DYNAMIC_COVER_THEMES` row + one category.js card. No new pages, no new cloud function, no new `PosterDrawer`.

**Douban TV themes** (`doubanTvCn`/`doubanTvForeign`/`doubanTvAnime` — 豆瓣高分华语剧集 / 9分国外剧集 / 9分动画; category tab 剧集): same movie pipeline, but the seed lists are scraped from Douban's own 选剧集 explore API rather than an editorial page — see `tools/douban-tv-seed/` (collector script + README). Two seed conventions are load-bearing and both were gotten wrong on the first cut. **Type filter is 电视剧, not 全部剧集** — 全部剧集 also pulls in animation and documentaries, which put 《葫芦兄弟》/《舌尖上的中国》 into the 华语 list; 电视剧 excludes 综艺/纪录片/动画 outright, so the three themes stay orthogonal and no 综艺 subtraction is needed. **Order is Douban's default 综合排序 (`sort=T`)**, the order a user sees scrolling the page — *not* `sort=S` (高分优先): within 9~10 almost everything at 9.6+ is a per-season entry of a long-running anime/US series, so taking the top N by rating drops the whole 9.0~9.3 band and loses first-screen entries like 《爱，死亡和机器人》/《鬼灭之刃》. Tag strings are `电视剧,华语` / `电视剧,国外` / `动画`, each cut at 250. 华语 runs a `score_range` of 8~10 rather than 9~10 — that filter yields only 168 titles at 9+, too few for 250 — so its front-end title is 「豆瓣高分华语剧集」, deliberately not 「9分」 (about 185 of its 250 sit below 9.0); change the threshold back and the title in `genericThemeConfig.js` + `category.js` has to change with it. Three API gotchas are documented there: only `tags` filters (`selected_categories` is silently ignored server-side), `score_range` rejects decimals, and any single `tags` combo caps at 500 items (partition on year tags if a list ever needs more). Seed rows carry `doubanId`, so `enrichThemeMovies` skips its Douban search entirely and pulls the detail directly — TV detail lives at `/rexxar/api/v2/tv/{id}`, which `/movie/{id}` 302s to and axios follows, and the search path's "non-movie subtype" quality gate doesn't apply to the manual-`doubanId` branch. `originalTitle` is deliberately set equal to `title`: these lists are ranked by *live* Douban rating, so ranks drift on every re-seed, and the title+year identity key is what keeps `_id` (and therefore users' marks) stable across re-runs.

**Arthouse theme** (`arthouse` — 文艺电影必修课): the one theme whose list is **authored rather than scraped** — no source site, no given ranking — so two things work differently. (1) `rank` is computed from a **Bayesian-weighted Douban rating** (the IMDb Top250 formula) instead of taken from a source: `enrichThemeMovies` now also stores `ratingCount` and gained a **`rerank` mode** (`{theme, rerank:{dryRun:true}}` previews, `{theme, rerank:true}` writes) that recomputes and rewrites `rank` in place. It runs server-side deliberately: 250 documents carrying `cover`/`summary` cannot be copied out of the console in full, so the arithmetic cannot be done locally. A sibling **`backfillRatings` mode** re-reads `rating`/`ratingCount` by `doubanId` without touching covers — that is the cheap fix when a theme was seeded by a build predating `ratingCount`, or when Douban ratings have drifted; `forceRefresh` would work too but re-downloads every cover and orphans the old ones in cloud storage. The vote threshold `m` is the **25th percentile, not the median** — at the median half the list collapses onto the mean and loses all ordering (a 9.5-rated and an 8.2-rated obscurity end up thousandths apart). (2) `originalTitle` is set equal to `title` so that re-seeding the same list only shifts `rank` — the "same film, new rank" branch matches on title+year and skips the Douban fetch; change it and every re-seed becomes a full re-fetch. Selection rule is authorial voice over genre (Kubrick sci-fi and Bong thrillers are in), capped at 5 films per director so coverage wins over auteur stacking. Because `originalTitle` is a Chinese title rather than the foreign original, the search path loses its English-title fallback —泛用 titles (《镜子》《爱》《诗》《记忆》) are the ones to check in `matchWarnings` after seeding. See `tools/arthouse-seed/README.md`.

**Sight & Sound theme** (`sightsound` — 视与听影史TOP250): BFI《视与听》 critics' poll, re-run once a decade (current edition 2022). Two things about the source shape the seed. (1) **"Top 250" is 264 films** — official places run 1..250 but carry heavy ties (22 films tied at 243, 18 at 225), and `rank` here must be unique and continuous because it generates `_id` and doubles as the list-page index, so `tools/sightsound-seed/collect-sightsound.js` flattens ties to a continuous 1..N (official place archived in `officialRank`, not displayed) and orders **within** a tie group by year+title — arbitrary but reproducible, which matters because BFI's own intra-tie order is CMS order and a re-scrape that reshuffles `rank` would drift `_id`s and misalign users' marks. Seven rows are then dropped via `EXCLUDED_TITLES` in the collector, in two groups. **Unseedable (2):** 《铁西区》(all three of its Douban parts return entry-level 403 `need_permission`, and it is a documentary so the search path's non-movie gate would reject it anyway) and 《西印度群岛》(zero ratings, no cover; the cloud-side detail fetch comes back empty, though a local fetch succeeds). **Search mis-matches (5):** `Blue Velvet`→《重访蓝丝绒》, `Twin Peaks: The Return`→《双峰：遗失的碎片》, `Pink Flamingos`→a same-titled Spanish film, `Twenty Years Later`→石晓华《二十年后再相会》, `Blue`→《蓝白红三部曲之蓝》 (BFI's is Derek Jarman's all-blue-screen experimental film). English common names colliding with same-titled Chinese films is this list's systemic risk (arthouse, being a Chinese-title list, does not have it), and the seeding run is **no help in spotting them** — `unmatchedMovies`/`matchWarnings` came back empty for all five, because the search did find *an* entry, just the wrong one. What does work is cross-checking the archived BFI director/country fields (`sightsound.source.json`) against the seeded Douban data: country mismatch narrows 262 rows to 8, then director settles it (different director = real mis-match, same director = co-production labelling noise). That is folded into `tools/audit-theme-match.js` as offline signal ⑤ and costs no Douban quota; the online year-check route is a dead end (Douban detail 400s after ~90 rows, and year is worthless when the collision is same-year, which `Pink Flamingos` and `Twenty Years Later` both are). The exclusions are applied **before** the tie flattening, so a re-scrape can neither reintroduce them nor shift every later `rank`. That lands the list at **257**, which is what the category card says. Unlike arthouse, substituting replacements is not an option: this is BFI's poll, and swapping in films it did not select would falsify it. Note `manual-ids.json` is keyed by `rank`, so adding to `EXCLUDED_TITLES` means re-checking every manual id whose rank sits after the removed row — otherwise those ids get pinned onto the wrong films. (2) The page's DOM is lazy-loaded and yields only part of the list; the full list sits in the inline `var initialPageState = {…}` blob (`componentState.results`, with rank/tied/name/year/director/countries), extracted by brace-balancing rather than DOM scraping. Seed rows carry a **locally pre-resolved `doubanId`** where one was obtained (`tools/sightsound-seed/resolve-douban.js`, review table in `sightsound.review.md`, human verdicts in `manual-ids.json`; 143/257 as of 2026-08-22 — see below — with the rest falling back to the cloud function's own search): the search path's title/year test is weak for this list (English common names vs Douban's French/Japanese `original_title`, leaving year as the only signal on 1916–2021 obscurities) and its non-movie gate would reject the serial/essay-film entries (《双峰：回归》/《电影史》), while a manual `doubanId` skips both search and gate. That resolver runs off `m.douban.com/rexxar/api/v2/search/movie` — the only search endpoint reachable from a dev machine (`j/subject_suggest` and the desktop site 302 non-Douban IPs), needs an `m.douban.com` Referer, and returns intermittent 403 `need_login`, so it backs off, caches everything, and re-tries rows recorded as misses on the next run — the endpoint rate-limits a dev IP hard after a few dozen queries (a `bid` cookie or a different UA does not help; the detail endpoint keeps working), so resolving the full list means re-running it across several sittings, and it is strictly an optimization — seeding works with the ids missing. Titles stay English in the seed (Douban rewrites them to 简体 and archives the English into `sourceTitle`, like letterboxd500); director/country are deliberately **not** seeded so the Chinese ones from Douban win. See `tools/sightsound-seed/README.md`.

**Books** (`maodun` — 茅盾文学奖 — as of this writing; parallel structure, independently extensible):
- `cloudfunctions/enrichThemeBooks` — takes `{ theme, bookList: [{rank, edition, year, title, author, ...extra}], idStrategy, forceRefresh, startFrom }`, writes into the **shared** `generic_theme_books` collection (`_id` prefixed `${theme}_...`). Matching strategy differs from the movie pipeline: books have no original-title/aka concept and print-edition years vary too widely to use as a signal, so matching is by **normalized-title exact equality** (with author-overlap as a secondary, non-blocking confidence check) instead of title+year — search candidates come from Douban's `cat=1001` (books) search page + `subject_suggest` fallback (same approach as `cloudfunctions/searchBookByTitle`), verified via the Douban rexxar book detail endpoint (same approach as `cloudfunctions/fetchBookFullInfo`). Same `sourceTitle` archival / resumable-batch / `skipValidation` conventions as the movie pipeline.
- `cloudfunctions/getThemeBooks` — read-side counterpart, query-by-`theme` against `generic_theme_books` + marks from `BookMarks` (not `Marks`). Response field is still named `movies` (not `books`) — matches `getMoviesData`'s existing convention for `douban_books`/`weread`, so `utils/dataLoader.js`'s `loadMoviesData()` wrapper stays theme-agnostic.
- `utils/dataLoader.js`'s `GENERIC_BOOK_THEMES` Set (checked before `GENERIC_THEMES`) routes a book theme id to `getThemeBooks`.
- Frontend: **one shared page set**, `pages/genericBookList/{list,share}`, driven by `?theme=xxx` + `utils/genericBookThemeConfig.js` (same shape as the movie config, plus a `source` field). Marks reuse the shared `BookMarks` collection (`status: 'read'|'wish'|'unread'`, `unread` deletes the record) — each generic book theme gets its own `source` value for bookkeeping (not required for correctness, since `bookId`s are already theme-prefixed and globally unique); `cloudfunctions/batchUpdateBookMarks`'s `source` param passes through arbitrary values (not just `'douban'`/`'weread'`).
- `pages/category/category.js`'s `_countThemeUsers` `themeConfigs` row needs `marksCollection: 'BookMarks'`, `idField: 'bookId'`, and `source` in addition to `collection`/`theme`; `DYNAMIC_COVER_THEMES` needs `collection: 'generic_theme_books'` (the field defaults to `generic_theme_movies` when omitted).
- `douban_books`/`weread_books` (the two pre-existing book themes) are **not** on the seeding pipeline — they keep their own dedicated `fetchDoubanBooks`/`fetchWereadBooks` cloud functions and read via `getMoviesData` (direct full-list scrapes, not search-matched seeding) — but since 2026-09 they **do** render through `pages/genericBookList` (config rows in `genericBookThemeConfig.js`, see Movie / Book Theme Pattern).

### Boxoffice Theme (`pages/genericList?theme=boxoffice`, 全球电影票房榜)
TOP100 by worldwide lifetime gross, **hardcoded** in `cloudfunctions/fetchBoxofficeMovies`'s `BOXOFFICE_DATA` — no scraper, no timer (`config.json`'s `triggers` is empty). Two actions: `seed` (upsert the array into `boxoffice_movies`, covers untouched) and `covers` (Douban cover → cloud storage, 50s self-guard + `startFrom` resume, `onlyRanks` for single-row fixes).
- **The live DB can run ahead of the hardcoded array.** As of 2026-08 it did — DB already held the current 100 while the source array was still a 2026-03 snapshot. Since `seed` deletes every doc whose `originalTitle` is not in the array, running it with a stale array silently reverts the live list, drops newly-charted films, and orphans those users' `Marks`. **Run `{"action":"seed","dryRun":true}` before the real `seed`** — it pages the live collection server-side and reports `wouldAdd`/`wouldDelete`/`grossChanged` without writing; a non-empty `wouldDelete` that is not the film you meant to drop means the array is stale.
- **`originalTitle` + `year` is the identity key** `seed` matches on. Refreshing numbers means editing `boxOffice` only — leave title/year/country/director byte-identical, or the record is re-created under a new `_id` and its marks orphan. `rank` is recomputed from `boxOffice` on every seed, so never hand-maintain it.
- Source is Box Office Mojo `chart/top_lifetime_gross/?area=XWW` (200 rows; rank/title/gross/year parse straight out of the HTML, and the host is reachable from a dev machine). Its title spellings differ from the array's on some entries (`Star Wars: Episode VII - …` vs `Star Wars: The Force Awakens`, `Jurassic World: Dominion` vs `Jurassic World Dominion`) — alias-map them when diffing, never "fix" the stored spelling.
- New rows should carry a hand-verified `doubanId`, so `covers` takes the rexxar detail directly instead of the 4-pass Douban search, which misfires on generic titles (《奥德赛》/《迈克尔》). Douban 302s non-cloud IPs, so when preparing a list locally the 中文名 + id have to come from web search.
- **Data-only updates need no app release** — the list page reads `boxoffice_movies` at runtime (`getMoviesData`, theme `boxoffice`); `utils/dataLoader.js`'s 24h client cache is the only lag. Releases are only for `pages/genericList/` changes (the page set is shared; the 票房 chip comes from `extraChips: ['boxOffice','year']` + `utils/movieFormat.formatBoxOffice`).

### Movie Rating Search (`pages/movie-search`)
Standalone feature, **not** part of the Top-N tracking pattern. Three pages: `input/` (search box + history cards), `list/`, `detail/`.

TVmaze is English-only, so `add.js` (`seasonHintsFrom`) bridges via the `原名:` field Douban's own results carry: 「行尸走肉 第八季 / 原名 The Walking Dead」→ `{cn:'行尸走肉', en:'The Walking Dead'}` → TVmaze `/search/shows` (name must match exactly after normalisation, else skip — #2/#3 are *Fear the Walking Dead*/*Origins*) → `/shows/{id}/seasons` → titles recomposed in Douban's own style 「行尸走肉 第一季」 (Chinese numerals) so title-normalised dedupe drops the seasons Douban already returned. Runs after the Douban list is already on screen and appends silently; `tools/test-search-movie.js` reproduces both passes locally without deploying.
- `cloudfunctions/fetchMovieFullInfo` — the heavy enrichment endpoint: same-CN-day cache → scrape Douban mobile detail (`m.douban.com` + iPhone UA, desktop is too aggressively anti-scraped) for rating/votes/IMDb ID/poster → OMDb API (needs `OMDB_API_KEY` env var) for IMDb score + RT Tomatometer → scrape Rotten Tomatoes HTML for **dual** critic (Tomatometer) + audience (Popcornmeter) scores, falling back to OMDb's single Tomatometer. **Rate-limited to one query per movie per CN calendar day** (protects the 1000/day OMDb quota); `forceRefresh` is itself 24h-throttled. Upserts `searched_movies` (cross-user shared master) + `user_movie_queries` (per-user history)
- `cloudfunctions/getMyMovieQueries` / `deleteMovieQuery` — per-user history list / single-entry removal (only touches `user_movie_queries`, never the shared `searched_movies`)
- `utils/movieFormat.js` — `decorateMovie()`, `cnDateStr()`, vote/RT-count formatting (thousands separators)
- `rottenTomatoes` field shape: `{ critic: {score,state}|null, audience: {score,state}|null, score: <mirrors critic.score, legacy>|null, fetchedAt }`

### Movie Guessing Game (`pages/guess/`, 每日猜电影)
Daily puzzle, three modes over one film pool (`movie_facts`). 交叉填格/线索猜片 share the predicate engine; 纵横填字 (`cross`) instead builds a crossword out of film titles. Modelled on moviegrid.io but deliberately **not** its data model — see the TMDB note below.

- **Why no TMDB.** moviegrid.io lets you answer with any film ever made, so it needs a full cast/genre index of all cinema; that is what TMDB is for. Here the rule is **答案须在标记吧片库内** (~4000 de-duplicated films across the existing 榜单 collections), so validation only ever queries our own data. Everything the clues need — `genres`, `actors`, `directors`, `countries`, `languages`, `durations`, `tags`, `intro` — is already returned by the **Douban rexxar detail endpoint** we've used all along (`m.douban.com/rexxar/api/v2/movie/{id}`), and every 榜单 row already stores `doubanId`. So the whole feature is a backfill, not an integration: no API key, no `douban↔tmdb` id alignment, and Chinese titles/华语片 coverage stays as good as the rest of the app. The one thing Douban's detail endpoint does **not** give is actor headshots (`actors` carries only `name`) — moviegrid shows those, we don't.
- `cloudfunctions/buildMovieFacts` — the data base layer. Sweeps `movies` / `oscar_movies` / `oscar_anime_movies` / `boxoffice_movies` / `generic_theme_movies` (same SOURCES list and same `MIN_GID_DIGITS` id-prefix guard as `buildMovieAlias` — **change one, change both**), de-dupes by `doubanId`, pulls the rexxar detail, and writes **`movie_facts`** (`_id = doubanId`). Deliberately a separate collection rather than new fields on each 榜单 doc: one film has N 榜单 docs, the read path (`getMoviesData`/`getThemeMovies`) is live traffic, and the engine wants "a film", not "榜单第 N 名". Carries `memberOf[]` (theme ids) and `movieIds[]` (that film's doc id in each 榜单) — the former drives 冷门度 and the 「入选 X 榜单」 predicate, the latter is what gets handed to `batchUpdateMarks` when a player wants to mark a film they just answered. Modes: `{dryRun:true}` / `{autoContinue:true}` / `{startFrom}` / `{forceRefresh:true}` / `{verify:true}`, 50s self-guard, `CONCURRENCY=3`.
- `cloudfunctions/getGuessPuzzle` — 出题. Builds predicates off `movie_facts` in two axes (人物轴 演员/导演 = rows, 属性轴 类型/国家/年代/评分/时长/片名字数/入选榜单 = cols), then picks 3+3 such that all 9 intersections are non-empty. **Three constants are load-bearing and were all found by an offline stress test, not by reasoning** (`MIN_PERSON_FILMS=8`, `PERSON_CANDIDATE_TOP=200`, `MAX_ATTR_RATIO=0.6`): with the naive settings (person floor 4, no top-N truncation, no coverage ceiling) 120 simulated days produced **13 solvable grids**; with them, 400 days produce **0 failures** and the median "hardest cell" goes from 2 solutions to 3. The coverage ceiling matters for a subtler reason — a column covering most of the pool (「入选豆瓣 TOP250」 in a库 built mostly from 豆瓣) constrains nothing, so the grid looks 2-dimensional but is really 1-dimensional. Puzzle is generated once per (mode, date) and stored in **`guess_puzzles`** with each cell's `answerIds` — that both makes 每日一题 identical for everyone and means `submitGuess` never re-implements a predicate. Seeded by `mode|date` (mulberry32) so concurrent first-callers agree; a deterministic `|retry{n}` re-seed covers the rare unlucky seed. ⚠ The puzzle doc holds answers — `exports.main` only ever returns the `sanitize*` view.
- `cloudfunctions/submitGuess` — 作答. `action`: `suggest` (输入联想) / `answer` (校验+计分) / `state` (进度) / `hint`. Progress lives in **`guess_records`** (`openid_mode_date`) server-side, not local storage, so a session survives backgrounding and device switches. Guessing a film **outside** the pool costs no guess — we have no data to judge it by, so charging for it would be arbitrary. 冷门加分 currently uses `ratingCount` rank within the cell as a proxy; real pick distribution is already accumulating in **`guess_stats`** for the switchover. `hint` is the 线索 mechanic wired into the grid: it reveals one facet of one correct answer for that cell, costs one guess, and picks the film by `hash(cellKey) % n` so repeated hints on one cell deepen on the same film instead of leaking three different answers.
- **纵横填字 (`mode: cross`)** — 7×7 网格里横竖交叉五部片名，线索是豆瓣简介第一句、把片名/演员/导演打成 `███`。词库天生窄（纯汉字 2 到 7 字片名 + `ratingCount >= CROSS_MIN_VOTES` + 线索质量闸门），`{crossStats:true}` 报每道闸门后还剩多少，低于约 120 条 `prepare` 直接拒绝出题。字池是**多重集**（一格一份字，重复字给多份），尺寸凑成 8 的倍数且不少于 24 —— 前端每行排 8 个，最后一行豁着看起来就是坏的。**校验按整条走，绝不按格**：逐格反馈会把二十来个字的字池变成暴力试错场。答案不出服务端，页面只拿到 mask + 线索 + 字池。
- Frontend: `pages/guess/grid/index` (3×3 + 作答弹窗 + 联想 + 求提示 + 答对顺手标记)、`pages/guess/cross/index` (填字) and `pages/guess/clue/index` (逐条解锁线索). grid/clue pass **`openid` explicitly to `batchUpdateMarks`** — that function requires it from the caller and returns 「参数不完整」 otherwise, while `app.ensureOpenid()` returns nothing, hence the local `resolveOpenid()` helper in each page. 分类页入口是「旅行打卡」下面单独的一栏**每日猜电影**，由 `category.js` 里写死的 `GAME_BLOCKS` 表驱动、复用每日主题那套横排块样式 —— 玩法不是榜单卡，所以刻意不进 `themes` 数组（没有 collection、不参与 `_countThemeUsers`、不进置顶）。
- **翻日期（只有 cross 有）.** `prepare` 备了 30 天，所以向后的箭头必须停在今天，否则明天的答案一点就到；往前翻不限。点今天的 `›` 弹订阅窗（topic `guessCrossDaily`，模板与 `top250NewEntry` 共用），次日上午 10 点推一条 —— 见 Subscription & Push。
- **填字页的版面（三个坑各有定论）.** 线索卡**锁死两行高**（服务端 44 字上限 ≈ 27rpx 下的两行），否则每切一条线索下面的棋盘就弹一次；棋盘只渲染 `viewRows`（真正有格子的那几行，存绝对行号所以点击坐标不受影响），否则 7×7 顶部的空行就是一大片白；页面底部留白**按实测字池高度给**（`_measureDock`）而不是写死，字池是 3 行还是 4 行随字数变。格子大小被宽度卡死（7 列挤在 702rpx 里），纵向富余只能给卡面，给不了格子。
- **出题走批量备题，按天现出题只是兜底.** `{prepare:true, mode, days, from, overwrite}` 一次备 N 天进 `guess_puzzles`：单个种子凑不出可解的盘是常态（3×3 约 1/2400），而跨天去重（人物/属性/影片冷却）也只有批量时做得到。⚠ `prepare` 返回的 `generated: N` 数的是内存里的清单 —— 它曾经在**一条都没写库**的情况下照样这么报，而且光看返回完全看不出来（页面拿到的一直是现出题那条路写的旧题，全文件只有它 set 过库）。验 `prepare` 跑没跑成，要查存下来的文档（`{mode, date, inspect:true}` 看 `createdAt` 是不是新的），不能看返回值。
- Bring-up order: deploy `buildMovieFacts` → `{dryRun:true}` (sanity-check the de-duplicated count) → `{autoContinue:true}` → `{verify:true}` → deploy `getGuessPuzzle` + `submitGuess` → 每个模式各跑一次 `{prepare:true}` → open the page. `getGuessPuzzle` fails loudly if `movie_facts` is empty.
- Open items: 剧集 (`subtype==='tv'`) are stored but excluded from both modes; a TV grid would be a mode flag, not new data. Also worth confirming before release that a game feature is acceptable under the mini program's current 类目 — 审核 归类 is the main non-technical risk here.

## Key Patterns

- **Mark statuses:** `'watched'` or `'wish'`, stored in `Marks` collection keyed by `(movieId, openid)`
- **Batch operations:** `batchUpdateMarks` cloud function atomically upserts multiple marks
- **Image optimization:** List views use thumbnail URLs via `imageCacheManager.getThumbnailUrl()`; poster walls use full-size originals
- **Cloud DB batch reads:** `MAX_LIMIT=100` with looped queries to bypass the 20-record default limit
- **getMoviesData:** supports `marksOnly` flag for lightweight mark refresh
- **Canvas posters:** Always use Canvas 2D (`type="2d"`), obtain node via `wx.createSelectorQuery().select('#id').fields({node:true})`, set `canvas.width/height` before drawing, use `wx.canvasToTempFilePath({canvas})` to export
- **Gender theming (growth):** Result page applies `.theme-female` class on container; poster drawer accepts gender from `input.gender` and uses blue/pink theme objects accordingly
- **Percentile display:** Show as `XX%` with label "超过XX%的同龄儿童" — do not use "P" prefix or "百分位" phrasing
- **Nutrition evaluation levels:** 7 levels per indicator using Z-score thresholds: ±3SD (重度), ±2SD (偏), ±1SD (略偏), within ±1SD (正常). Yellow `.mild` class for 略偏, red `.warning` for 偏/重度
- **Daily theme — week/month math:** Mon-start everywhere. `dayOfWeekMon = (getUTCDay() + 6) % 7`. Stats and share haven't unified — stats fetches per-period on demand (week=Mon~Sun, month=1st~last), share uses a 30-day rolling window for day/week and a separate on-demand natural-month fetch (`_ensureMonthData()`) for the month poster's calendar layout
- **Daily theme — top toast:** never use `wx.showToast` in `pages/daily/*` — it can't be repositioned. Use `require('../../../utils/dailyToast.js').show(this, '...', { icon: 'success' })`; pages must include the `<view class="top-toast ...">` node and `data.toast` field
- **Ad strategy preference (per `MEMORY.md`):** category page rejects interstitial ads; favor improving existing slots over adding new ones
